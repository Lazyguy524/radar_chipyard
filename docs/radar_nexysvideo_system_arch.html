已经修掉的硬件问题
  • MIG 黑盒只有 4-bit AXI ID，而早期共享 xbar 的内部 ID 一度超出这一范围，导致 MM2S 读返回错路由。
  • 修掉这个问题之后，老的“MM2S_LENGTH 一写就炸”和 a5a5... 污染读回现象已经消失。
  • 后来为 `ExtTLMem` 增加 uncached alias 时，又出现过一次 `tl_mem source` 宽度在顶层被截断的问题，这一层也已经修正。
当前从硬件角度可以明确认为：DDR 主存口、MM2S 读返回路径、S2MM 写回路径、uncached alias 接法都已经被收口到可用状态。
仍然成立的系统现实
  • Rocket D-cache 与 DMA 之间仍然不是自动 coherent 的。
  • 如果继续让 CPU 通过 cacheable DDR 视图访问 DMA buffer，就必须做 cache maintenance。
  • 如果改用 uncached alias，则可以绕开这条约束，但当前软件需要明确区分 CPU alias 地址和 DMA 原始地址。
  • 当前 DTS 里还没有正式描述 uncached alias 视图，这一层后续可以继续工程化。
当前系统已经跑通，但“是否需要 cache maintenance”取决于你选用哪条 buffer 访问路径，而不是 DMA 本身忽好忽坏。

后续最值得记住的几点
  • 当前平台已经不是“零散模块打通”，而是一个具备真实 DDR 数据搬运能力的可运行原型。
  • 后续如果继续做雷达预处理、NN 加速器或其它 AXIS 算法块，最自然的接入位置就是 MM2S 和 S2MM 之间的 stream 段。
  • 当前应该优先把 DMA buffer 使用协议文档化，明确什么时候走 cache-maint 路径，什么时候走 uncached alias 路径。
  • 如果后续要继续工程化，可以把 uncached alias 进一步写进设备树、统一封装为固定软件 API，并逐步减少 bring-up 特殊知识。
