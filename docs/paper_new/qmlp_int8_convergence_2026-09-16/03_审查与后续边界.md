## 已完成的闭环

1. 数据恢复：完整 train 357,780 条的原始点簇、标签、点数及 21 维软件特征核对通过；当前硬件镜像与前次 49,255 条子集逐项一致。验证输入直接复用既有缓存，并记录 SHA。
2. 训练对齐：模型输入就是现有硬件特征；输入归一化折叠进第一层，避免离线模型依赖板上不存在的预处理。
3. 量化一致：尺度和乘数只由训练数据确定，QAT 全程冻结；训练和评价的前向使用同一整数舍入规则。
4. 导出一致：重载候选参数、逐层 NumPy INT64、原 C 算术主体及 QAT 前向一致；完整验证数据与额外 1,028 条边界/随机输入均通过。
5. 受控停止：两个 seed 均按训练损失规则停止；原始逐 epoch 曲线完整保留，未选最高验证 F1 checkpoint。

## 不能据此增加的主张

- **不能称为全局收敛。** 相邻窗口平均损失平台是预算内的操作性指标，可能受到小幅震荡影响；末五个 epoch 的验证 F1 仍有约 0.20–0.24 个百分点跨度，权重未必完全稳定。
- **不能称为新独立测试成绩。** validation 已参与长期开发；旧 test 曾参与 K 选择。需另行确定未参与开发的最终评价来源，不能通过重命名 split 洗掉选择历史。
- **不能称为新增硬件实测。** 新包未接入 RTL release loader，也未新建 bitstream。原有 ELF、ROM、位流使用原模型；新权重与乘数的物理时序需要重新测。
- **不能把总收益归因于单一技巧。** 全量训练、当前镜像输入、归一化折叠、训练损失和固定尺度 QAT 同时构成新协议。与旧模型的比较证明新候选在开发验证上的改善，不分离每个因素的因果贡献。
- **不能证明 QAT 优于浮点模型。** 相对各自浮点预训练，两 seed 的配对序列区间都跨零。合理表述是本轮整数候选保留了接近浮点参考的分类质量；不能把微小差值写成量化带来的确定优势。
- **不能证明所有近似都无害。** 当前统计表示可能仍丢失信息；本轮只建立更强的匹配基线，没有重新比较准确协方差、逐特征定标或新特征维度。
- **不能将真值轨迹分类写成完整在线感知。** K7 无时间过期、传感器姿态与真值聚类等边界保留，训练闭环并未修正这些问题。

冻结激活尺度下，validation 中隐藏激活等于上限 127 的比例已记录在整数校验汇总。这是落在裁剪上限的比例，不能当作严格的“超过上限而被裁剪”的频率；权重裁剪比例也单列保留。

## 本轮停止位置

两个候选都保留为特征选择研究的对照基线，不按验证分数只展示最好者。下一阶段先完成样本与特征筛选证据，暂缓新参数的 RTL 接入。

后续研究确定候选后，RTL 阶段应建立独立配置和输出目录，以对应 INT8 特征、同一批输入和新参数为身份，先小样本 RTL 验证，再考虑物理实现。现有 Scala 参数只是交付格式，当前硬编码 release 路径没有切换。新增乘数会改变常量乘法展开，旧时序报告不自动适用。

在论文研究上，先把这一基线固定下来；新的统计表示或精度分配方法只有在同等训练与导出约束下带来稳定、跨序列的收益，再进入硬件成本比较。当前结果属于训练部署一致性与工程基线完善，不能直接冠以新算法创新。
