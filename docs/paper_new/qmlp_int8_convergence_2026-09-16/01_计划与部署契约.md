# 当前硬件特征对应的冻结 INT8 基线

2026-09-16。承接用户“继续开发，希望得到收敛结果”的要求。本轮先完成可重复的整数训练与导出基线，再判断数值平台期；不预设必须涨分。使用项目 `radar-paper-knowledge` 技能，以下是同一执行者的执行前评审，不冒称独立审计。

## 冻结范围

[机器可读计划](plan.json)在新训练前保存。仅使用当前部署 Feature21 镜像，保持 21→64→32→2、二分类、原 K7 和真值轨迹构造。完整 train 357,780 条、113 个序列；复用上一轮完整 validation 的 80,450 条、27 个序列。历史 test 不用于新评价或选择；目前没有可以宣称完全未参与开发的独立测试成绩。

两种随机初始化 seed 7/17，共两条训练轨迹，每条包含：

1. 训练集均值/标准差归一化，浮点网络预训练 20 epoch。
2. 将输入标准化折叠进第一层权重和偏置；在训练集确定的最多 16,384 条固定校准样本上确定尺度，得到 PTQ 对照。
3. 冻结输入、权重、激活尺度及两个整数重定标乘数，进行最少 20、最多 60 epoch 的 QAT。
4. 使用训练损失平台期规则停止；验证集只记录趋势，不挑选最佳 checkpoint。两个 seed 全部保留，不按验证集排名只展示最好者。

QAT 学习率按计划从 0.0003 开始，每 20 epoch 减半，不新增参数搜索。CPU 2 线程、GPU 0 作业；完整缓存最多 600 s，两条训练轨迹合计最多 900 s，导出校验最多 600 s；输出软上限 256 MiB。超时、数据不符、算术不符即停止，保留失败证据。

## 标准化折叠

浮点预训练第一层为 `W ((x-μ)/σ) + b`。折叠后：

`W_fold[:,j] = W[:,j]/σ[j]`

`b_fold = b - W_fold μ`

推理直接接收原 Feature21 INT8 输入 x，不增加在线标准化算子。浮点代数等价需要检查；随后对折叠权重量化，会引入新的误差，因此必须单独记录 PTQ，并通过 QAT 检查可恢复程度。折叠并不保证 INT8 权重精度足够。

## 对齐现有整数契约

- 输入：现有 Feature21 对称 INT8 值，尺度 1 表示直接按整数单位计算；第一层权重已经吸收原单位及标准化。
- 权重：每层统一尺度，对称 INT8 [-127,127]；偏置 INT32。
- 累加：INT32；先做覆盖所有合法输入幅度的保守溢出上界检查。
- 第一、二层：`round_even(acc × multiplier / 2^16)`，再 ReLU、裁剪 [0,127]。
- 第三层：直接输出两个 INT32 累加值，不做最终重定标。
- 乘数由正数 `floor(ratio × 65536 + 0.5)` 得到，匹配现有 Scala 参数读取端。乘积舍入是 ties-to-even，两者用途不同。

QAT 前向在 Float64 中表达上述整数数值，反向采用 STE；要求整型点积和乘积都落在 Float64 可精确表示的整数范围内，并与独立 NumPy INT64、现有 C 函数主体逐层对拍。不能仅凭 fake-quant 标签声称与硬件一致。

源码依据：[现有 C 推理](../../../tests/radar-feature21-qmlp-cpu-fullchain-profile.c)、[现有 QMLP RTL 与参数加载](../../../generators/chipyard/src/main/scala/radar/RadarQMLP.scala)、[本轮实现](common.py)。现有 RTL 的 release 路径仍指向旧参数；新 C/Scala 参数只输出到独立候选目录。新权重和乘数可能改变常量逻辑与时序，必须经过独立 RTL、位流和板测后才能报告实际硬件效果。

## “收敛”的操作性定义

QAT 至少 20 epoch 后，比较固定训练校准子集最近 5 epoch 与此前 5 epoch 的平均交叉熵。差值绝对值不超过 `max(0.0001, 前一窗口损失 × 1%)`，连续两次满足，记为训练损失进入平台期。否则最多运行 60 epoch，明确记录未达平台期。

另行报告末 5 epoch 验证 Macro-F1 的跨度是否 ≤0.003（0.3 个百分点），该条件不用于停止。平台期可能发生在质量不佳的位置；不等价于全局最优、独立泛化保证或两个 seed 等价。训练损失、整数一致性、分类质量和硬件验证分别给出结论。

## 预检与失败边界

[preflight.py](preflight.py)使用合成数据检查折叠、正负半整数舍入、C/NumPy/Torch 逐层一致、反向梯度有效，以及 eval 的 batch 不变性。通过后才启动完整训练缓存；缓存与原始软件特征逐条核对，并与上一轮 49,255 条镜像输入交叉核对。

最终候选需要完整 validation 的逐层整数比较、随机和极端输入比较、重载导出文件一致、不同 batch 和顺序不变。全部通过仍只授予离线整数候选资格。真值轨迹、无时间过期的旧 K7、历史 test 参与开发等限制沿用原审计，不因本轮冻结尺度而消失。
