# 软件契约、共享计算及复现

本轮仅新增软件。旧 RTL/SoC/位流及以前失败门槛保持原样；新模型不能因为仍有 21 维就直接装进旧位流。

## 数据与历史

原始数据来自本地 RadarScenes 原始 HDF5，划分依已有 split_manifest.csv.gz；prepare.py 重建观测并核对 SHA。训练为 113 个序列、357,780 个原保留观测及 474,582 个真实 1～2 点观测；开发验证为 27 个序列、80,450 个原保留观测及 97,734 个真实少点观测。

类别 0 是原始标签 7/8（行人及行人组），类别 1 是 0/1/2/3（车辆相关类）。其他类别和空 GT track 不在这个任务域内。原多数标签映射保持，原始标签并列时取较小 ID；混合二类的观测数由审计单列，不能据二分类 F1 宣称没有数据偏差。

每次使用同序列、同传感器、同 GT track 最近六个先前保留的 ≥3 点观测与当前观测；1～2 点观测不更新历史。记录时间跨度的原始 timestamp 单位及当前/最早历史质心位移。历史不设时间上限、不做跨帧姿态补偿。真实少点的两个视图分别只用当前点，以及用相同历史规则累积后的点；它们来自同一批观测，不能当两个独立样本集。

合成少点每个保留观测抽取固定一份 1 点、一份 2 点，历史部分不变；不解释成真实遮挡模拟。两覆盖策略按类别×当前点数×历史数量的共同支持分组匹配，不能排除距离、物体组成等组内分布差异。两者共享含真实少点的训练校准池，所以“合成覆盖”仅指优化器的少点样本来源，不意味着完全未接触真实少点统计。

## 21 槽位定义

点输入四通道 x/y/补偿径向速度/RCS，均为 signed Q8.8。N 为融合后点数，范围 1…511。两种表示只比较第一矩，其余代理保持不变。

| 0-based 槽位 | 定义 |
| --- | --- |
| 0 | N（内部先左移 8 位） |
| 1、2 | x/y 均值代理或中心化均值 |
| 3、4 | x/y 跨度右移 2 位；不是方差 |
| 5、6 | x/y 极差 |
| 7、8 | 各点近似距离的最小/最大值 |
| 9 | 按槽位 1、2 计算的近似中心距离 |
| 10 | y 极差；不是协方差 |
| 11、12 | 槽位 3、4 的最大/最小值；不是特征值 |
| 13 | 旧 LUT 密度编码，已经量化的槽位 |
| 14 | 径向速度均值代理或中心化均值 |
| 15、16、17 | 速度极差右移 2 位、最小值、最大值 |
| 18 | RCS 均值代理或中心化均值 |
| 19、20 | RCS 极差右移 2 位、最大值 |

代理均值使用 `sum >> ceil(log2(N))`，因此 N 非 2 的幂时存在系统缩小；移位本身不等于无偏均值。均值修正以首点为原点 a，S=Σ(p−a)，I=round_even(2^b/N)，先把 S×I 舍入至多保留 4 位小数，再舍入并加回 a。初始 b=24，固定权重检查 b=12/16。两次舍入、INT16 边界和最后 INT8 饱和均以 C 实现为准，不称完全精确实数均值。

两种表示均沿用已冻结的逐特征尺度。原始整数特征乘 `2^(-shift[j])`、ties-to-even 后夹紧到 [−127,127]；21 个 shift 依次为：

`10,8,8,6,5,8,7,8,8,8,7,6,4,0,6,7,8,8,6,5,7`

这些常数来自既有 train 定标，不在新 validation 上重估。网络 21→64→32→2；INT8 权重和隐藏激活，INT32 偏置/累加/logits，隐藏重定标 ties-to-even、ReLU 限幅 0…127。标准化折叠进第一层，没有运行时归一化。

## 成本口径

两种表示均一次扫描，更新四通道一阶和、极值及逐点近似距离；不新增每点二阶乘法、平方根或特征值计算。均值修正额外做四通道减原点、簇结束后的四个倒数乘法，四个均值共用一次倒数读取；训练覆盖方式不增加部署网络结构。

网络每观测有 `21×64 + 64×32 + 32×2 = 3456` 个权重乘累加，权重 3456 字节、98 个 INT32 偏置 392 字节，共 3848 字节，不计尺度/对齐/缓冲。输入 21 字节，两层隐藏合计 96 字节；若复用缓冲，实际占用取决于实现。

N≤511 时原直接和 signed 25 位足够；中心化差值 signed 17 位，一阶和 signed 26 位足够。参考 C 仍采用 int64 中间量，最终发布检查逐层上界；不把理论位宽叫已经裁剪的电路。倒数最大值 2^b，需要 b+1 位；512 项理论表大小 Q24/Q16/Q12 分别为 12800/8704/6656 bit。当前 C 的 Q24/Q16 表仍是 uint32_t，Q12 路径以整数除法生成倒数，并非已实现压缩 ROM。三个配置的实际 FPGA 面积、频率、周期和能耗均未测量。

## 复现与冻结

环境：Python 3.10、NumPy 1.26.4、PyTorch 2.4.1 CPU、h5py 3.11.0；CPU 两线程，无 GPU。研究脚本拒绝覆盖已有阶段目录。

```bash
PY=/tmp/radar_training_audit_20260915/bin/python
D=docs/paper_new/software_convergence_2026-09-17
# 以下是已执行顺序；重跑须新建独立研究目录并修改 sw_common.py 的 LOG。
$PY "$D/prepare.py"
$PY "$D/pools.py"
$PY "$D/evaluate.py" --baseline
$PY "$D/backup_git.py" --phase before
$PY "$D/train.py"
$PY "$D/evaluate.py"
$PY "$D/build_package.py"
$PY "$D/freeze_exports.py"
$PY "$D/report.py"
$PY "$D/final_audit.py"
```

科学源文件、输入特征、输出尺度和预检在 training/source_manifest.json 冻结；训练结束重新校验。后加的汇总/审计脚本用于结果整理，不称为训练前注册。所有种子最终轮保留，不按验证最高轮或最高种子择优。

独立 C 包位于 `logs/software_convergence_20260917/package/`。解压候选后执行 `gcc -O2 -std=c99 candidate.c -o candidate`，再 `./candidate example.int16le`。每目录的 contract.json、params.h、candidate.c、example.json 是同一候选；不与旧位流或旧板测速度混用。

训练级复现还依赖原始 RadarScenes HDF5、原划分清单和既有 `mechanism_convergence_20260916` 冻结输入/原生镜像。它们的路径与 SHA 在 preparation.json、training/source_manifest.json 及旧研究归档中登记；本轮归档不重复打包原始雷达数据。单个 C 候选无需这些训练资料或 Python 即可运行，完整训练复现不能仅靠一个 C 压缩包。
