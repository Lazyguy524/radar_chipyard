# 后续验证只解决哪些问题

## 代表方案已固定

| 方案 | 用途 | 已有认识 |
| --- | --- | --- |
| A：普通训练＋逐特征定标 | 基础参照 | 保留原任务上的判断能力 |
| B：扰动训练，同一表示 | 少点/形态变化对照 | 整体困难条件改善，部分自然分组退步 |
| C：正确判断保护，同一表示 | 取舍对照 | 减少新错误，但牺牲部分形态变化收益 |

方法比较继续使用原三个 seed，逐项报告好处与代价。seed 7 仅因是冻结列表第一项而被用于这次硬件功能验证；不把它的分数代替三 seed 方法结论。不把 C 未满足旧推广门槛改写成已经满足，只将它保留为解释取舍的候选。

矩统计、输出编码和精度实验仍是前面解释“为什么保留简单共享结构”的证据，不能在论文中消失。当前实现选择只说明新增复杂统计尚未证明必要，并不证明 proxy 或 21 维普遍最优。

## 质量确认

已有 validation 用于多轮探索；历史 test 也曾用于旧项目决策。两者可以如实报告，但不称为首次独立验证。额外五序列无当前目标类别的有轨迹点，不能补齐此缺口。

如果获得新的适用标注数据，先冻结场景/轨迹划分、类别映射、点过滤、K7 历史规则、单位/坐标转换，再生成特征和评分。数据集变化可能伴随传感器与标注定义差异，必须核实，不能直接拼接。

评价须包含整体 macro-F1、两类 precision/recall/F1、混淆矩阵，以及原已固定点数、形态、距离、历史支持分组。报告样本和独立序列数量，置信区间按序列重采样；支持不足组只描述，不制造“显著”结论。原训练、原模型、原阈值不再根据新确认集调优；如果调整，明确该数据转为开发域。

若目前拿不到新数据，可以完成实现验证和开发域取舍研究，论文的外推范围相应收窄。新做一次旧 test 或把 validation 改名，不会产生独立性。

## 匹配的硬件验证

本次独立 Feature21→QMLP RTL 通过后，还需要把同一候选接入独立 SoC 配置。需要一起绑定：特征定标、网络参数、源码、ROM、生成 RTL、时钟、位流、ELF、点簇输入、预期 logits 和板端日志，逐项保存 SHA。

先做正确性，再测资源、延迟和吞吐。三方案使用相同输入、同一 lane 数/时钟和计时起止，分别记录模型常数导致的综合差异。小目标与多点目标分开列；CPU 特征、QMLP-only、Feature21-only、full-chain、DMA 和端到端窗口不得混用。PMU 记录用于解释瓶颈，不代替板测。

旧板测可以作为历史参照，但不能把新模型分类质量与旧模型位流的成本拼成一个新结果。当前仿真包含人为输入空拍和输出阻塞，其周期数首先是正确性测试记录，不能作为最终性能指标。

当前不重启暂缓的 Gemmini 板测线。后续需要这一比较时，另绑定同一任务、量化和后处理契约；不能再用原生 Scale 仿真值冒充无 Scale 板测。

## 本轮后的接续顺序

1. 根据实际 RTL 对拍结果决定是否具备接入 SoC 的条件；任何错误先定位到表示、定标、参数、协议或算术，不改模型掩盖错误。
2. 使用独立配置生成完整 SoC 仿真和板测用固件，保留原发布版。部署正确性与算法推广是不同判断。
3. 补齐匹配资源/时序与板测，并保留独立质量确认的真实状态。
4. 将论文论证写成“假设—对照—证据—取舍—实现”，展示关键退步，避免把状态机和寄存器说明当作贡献。
