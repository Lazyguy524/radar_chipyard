# 从训练结果推进到实际计算结构

用户在 2026-09-17 明确要求继续推进。停止上一轮训练仅是预算和方法探索的停止，不能当成整个项目暂停。

原问题保持：**在点数和目标形态变化时，哪些近似会损害分类稳定性？能否针对这些误差，用更合适的统计表示、精度分配和共享计算结构，获得优于现有实现的质量—成本取舍？**

## 执行前决定

1. 保留 A 普通训练、B 扰动训练、C 正确判断保护作为有不同收益和代价的代表；D 的负结果留在原包。三者均不是已批准替换旧工程的发布版。
2. 三者使用同一 proxy 特征和相同 21→64→32→2 网络大小。先验证共同输出定标与现有 QMLP 计算结构能否正确衔接，不添加尚未证明必要的矩统计硬件。
3. 不再训练。RTL 选原种子列表第一项 seed 7 作为实现样本，不挑分数最好的种子；算法结论仍依据三 seed。固定 4 lane 是与现有默认结构对接，不用于与其他 lane 或 Gemmini 宣称最终性能。
4. 先 Python 预检，再复制当前 Chisel 到新目录和新 package，改动只有逐特征定标、参数来源和验证顶层。原始 RTL、权重、位流不修改。
5. 复用 80,450 条开发 validation 做功能对拍，不新增历史 test 评价；另外用确定性的边界点簇检查符号、点数、饱和、握手和中止恢复。

## 自审：为什么这个步骤合理

- **真实缺口**：旧 Feature21 对大多数特征统一乘 105 再右移 16；新表示在饱和前按各特征不同的 2 的幂次定标。旧输出已经丢失信息，不能简单在旧 INT8 之后重标定恢复，也不能只换网络 ROM。
- **选择偏差**：已熟悉 validation，不能把本次对拍叫独立测试。没有新目标类别标注数据是评价缺口，硬件对拍不会填补它。
- **资源解释**：相同网络尺寸、同样算子结构不意味着常数不同的综合面积/时序完全相同。保留可综合实现与模型绑定，成本等待匹配综合及板测。
- **范围控制**：只做三种已冻结代表的实现检查；遇到不一致定位实现问题，不能修改权重/尺度挽救结果。失败记录保留。
- **论文意义**：把“数值与分类取舍”对应到可执行结构，为后续质量—成本同配置测量铺路。不是增加一种声称原创的训练算法。
