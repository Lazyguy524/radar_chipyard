# Scheiner 2018 读后核对：21 维、数据来源与二分类论证

日期：2026-09-15。性质：原文与仓库核对、实验设计；未新增训练、FPGA 构建或板测。Gemmini 比较套件的缺口已[单独暂存](00_暂缓的Gemmini板测任务.md)。

后续讨论：[固定 21 维与资源论证修正](05_固定21维与资源论证修正.md)。保留 21 维为当前部署基线；后向消除首先是信息与冗余分析。QMLP8 的 21/20/18 维均为每行 3 个八路计算块，保持接口时也都传 32 B，不能按删维比例宣称节省硬件资源。

最值得改变的论文论证是：**21 维应由任务需求、特征组实验和实际实现成本共同支持。文献提供候选设计依据，不能替本项目证明 21 维最优。** 当前已有 14/18/21 三组软件结果，不是从零开始；但它们的训练条件与划分仍需溯源。

建议阅读顺序：

1. [逐项对应表](01_21维逐项对应.md)：10 项统计类型可对应、3 项反射强度相关、2 项几何定义有差别、6 项未找到明确逐项对应。这是软件定义的审慎分类，不是 10 项数值完全相同，也不是余下 11 项原创。
2. [数据与二分类边界](02_数据集与二分类论证.md)：RadarScenes 官方把本文列为早期子集研究；不能写成两套完全无关的数据。两类 F1 较好也不能证明数据或划分无偏。
3. [特征排名与待补实验](03_特征选择与训练资料补充.md)：先补训练证据，再做受控消融；最终评价部署的近似特征与 QMLP。
4. [核对记录](04_核对与引用边界.md)：修正读书笔记中容易引起误解的表述。

本轮还确认了一点：当前 RTL 的标准差、协方差特征值和方位角槽位采用代理量。**21 个接口槽位不等于 21 个独立的精确统计量。** 应把“软件特征定义 → 固定点/代理表示 → 分类变化与成本”写成算法硬件化的研究问题，不能把软件公式直接当作硬件已实现公式。

论文可暂用以下措辞，补实验后再充实依据：

> 本文面向已关联雷达目标点簇的行人/车辆二分类，研究固定维特征表示、整数近似及其在 RISC-V SoC 上的流式实现。当前部署采用 21 维输入；已有不同维度模型结果提供了比较线索，特征组的独立贡献及其与实现成本的关系仍需在统一划分下验证。本文分别评价分类质量、软件与硬件表示差异以及板端运行开销，结论限定于所定义任务和验证数据。

“仍需验证”是当前资料状态，不能在正式定稿时用未来计划代替实验结果。二分类任务的边界在任务定义处说明，主要误差在结果与讨论处解释，不必在每一章重复自我否定，也不应隐藏标签合并规则或失败类别。

原论文：Scheiner 等，*Radar-based Feature Design and Multiclass Classification for Road User Recognition*，IEEE IV 2018，[DOI](https://doi.org/10.1109/IVS.2018.8500607)，[作者预印本](https://arxiv.org/abs/1905.11256)。已存[本地 PDF](../training_and_gemmini_retest_2026-09-15/literature_supplement/scheiner2018radar_arxiv1905.11256v1.pdf)；[Zotero 导入书目](../training_and_gemmini_retest_2026-09-15/literature_supplement/supplement.ris)已有此条，无需重复导入。
