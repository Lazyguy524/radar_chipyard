# C 实现与复现入口

本包交付 29 个独立 host C 候选，另一个[编码包](../moment_encoding_2026-09-16/README.md)交付 6 个。每个包含单遍点统计、固定输出尺度、折叠标准化后的 INT8 参数及整数网络；全部在 80,450 个原保留验证簇上核对特征与最终 logits。原训练还逐层核对 C/NumPy/QAT，不能把最终预测碰巧相同误作整数一致。

## 使用单个候选

解压 [candidate_c_bundle.zip](candidate_c_bundle.zip)，进入例如 `augmentation_proxy_seed7/`：

```bash
gcc -O2 -std=c99 candidate.c -o candidate
./candidate example.int16le
```

示例的预期特征/logits 在同目录 `example.json`。这只是选择一个固定 seed 演示命令，并非挑最高分模型。输入文件为无头、小端、每点四个 signed int16 Q8.8：x/y/补偿径向速度/RCS，点数 1…511；输入是上游已经构造好的一个簇，GT 轨迹及 K7 融合不在这个 C 程序内。输出 21 个 int8 特征、两个 int32 logits 和类别编号。

源码通过编译时 `FEATURE_FLAGS` 去掉不用的二阶乘积。原代理没有新增空间乘法；均值修正共享四个一阶和和一次倒数；共享矩再增加每点 dx²、dy²、dx·dy。只变空间矩的版本不会顺带改输出均值。编码方案多三次簇末整数根，并复用两轴根号结果求最大/最小。

## 重新检查与重新训练是两种动作

- 只读原始结果：`logs/mechanism_convergence_20260916/{factorial_v2,augmentation_v2,*_evaluation}/summary.json` 与 `logs/moment_encoding_20260916/{training,evaluation}/summary.json`。
- 重生图表与分组汇总：`make_report.py`、`summarize_groups.py`；不改模型或原始预测。
- 重训入口：主包 `preflight_prepare.py` → `train_fixed_v2.py --stage factorial` → `continue_experiments.py`；编码包为 `prepare.py`、`train_encoding_v2.py --stage encoding`、`evaluate.py`、`build_candidates.py`。**这些脚本路径冻结且拒绝覆盖已有成功目录，重跑需复制成新的实验目录并修订新计划。不要直接覆盖本轮输出。**
- `train_fixed.py` 和编码包 `train_encoding.py` 保留失败版本用于溯源；成功版本带 `_v2`。包装器的未使用旧辅助函数不作为入口。

实际运行环境为 Python 3.10、NumPy 1.26.4、PyTorch 2.4.1 CPU、h5py 3.11；绘图环境为 Matplotlib 3.7.5。训练/评价两 CPU 线程顺序执行，无 GPU 工作。原始 HDF5 来源 SHA 在 raw 阶段记录中，模型参数及源码 SHA 在每阶段清单。读取这些目录时避免把缓存、派生删点视图与原始独立样本混算。

本包没有编译 RISC-V ELF，没有写入 Scala/RTL/FPGA。相同网络大小不意味着可直接替换旧 ROM，因为各表示/输出尺度和权重必须匹配；旧 Feature21 接口也不自动拥有新均值/矩统计功能。代码中的 int64 与查表方式是经过界限检查的功能参考，RTL 调度、流水和物理位宽应在方案冻结后另行证明。

最终 FPGA 资源、频率、功耗及性能仍应来自相同候选配置的综合/实现与上板实测，不能从 host C 运行时间或逻辑运算数推导最终加速比。
