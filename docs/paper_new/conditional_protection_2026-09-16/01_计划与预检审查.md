# 两种条件保护训练：运行前审查

主问题和设计理由见[设计账本](00_设计账本与主线.md)，机器可检验约束见[plan.json](plan.json)。本轮采用单执行者审查和 Python 模拟，非第三方独立评审。

只训练两种方法×seed 7/17/37，每条 20 FP32＋60 冻结 QAT，使用原完整 train、原 proxy 逐特征尺度和 `21→64→32→2`。视图概率仍为 50% clean、25% 均匀四分之一、25% 中心一半；每轮每行只采一个视图，学生前向/更新次数和旧增强 B 一致。旧 A/B 同 seed 用于对照，未挑最好模型。

`clean_guard` 损失为原类别加权交叉熵，加上温度 2 的教师→学生 KL。KL 仅在抽到 clean 且同 seed 旧 A 教师预测正确的训练行生效，系数 1，按全 batch 类别权重归一。教师 logits 必须乘该教师最终输出尺度再计算软概率，不能把未还原尺度的 int32 累加器直接 softmax。教师是 train 学得的既有固定模型，不读验证分数来选择。

`group_guard` 保留相同 KL，将任务损失设为一半原全局交叉熵、一半组加权损失。18 组为视图×原观测历史数（0/1–5/6）×原当前点数（以 train 中位数为界）；边界由 train 得到，不按验证表现寻找。组权重初值均匀，每轮按 train 组损失以步长 0.05 乘法更新。mini-batch 缺席组不参与当次组损失，按当次出现组权重重新归一；这是明确的随机近似，不保证实现总体 minimax 最优。源观测支持是在人工删点前的属性；不将其写成删点后真实可用历史。

两方案共用 train 混合均值/方差和 QAT 校准行。组信息、教师均仅在训练期使用，部署仍是单个整数网络。离线教师推理与训练损失计算的额外费用单独记录，不能声称训练计算完全相同。

运行前 Python 检查目标：相同分布 KL=0；教师错误和非 clean 行不受保护；对 logits 同加常数结果不变；有限梯度；组权重向高损失组移动；两种方法在少量 train 行完成 warmup/QAT 微步并通过整数前向一致性。全量训练之前先读[预检结果](../../../logs/conditional_protection_20260916/preflight.json)。

接受门槛提前固定，要求三个 seed 都通过：clean 相对 A 的 F1 下降≤0.1 pp；11 个保留观测条件相对 B 的 F1 下降≤0.1 pp；均匀四分之一/中心一半相对 A 至少提高 0.5 pp；真实 sparse_context 的六历史和近距离组相对 A 的 F1 下降≤0.2 pp；所有支持充分的 sparse_context 组 accuracy 下降≤0.5 pp；clean 对 A 的负翻转数不高于 B。支持门槛沿用 ≥100 行、≥3 序列、两类存在。门槛为本次开发决策，不是业务安全保证。

风险与停止：小组少量翻转可触发保守门槛，失败不等于统计显著更差；教师 train 正确不保证其他域正确；自然少点样本本轮仍未进入训练，保护迁移可能失败。无论结果如何六条后停止，不增加损失系数、教师、表示或 seed。全部旧 test 不新增评分；缺席历史清单的序列先做标签/身份审计，未建立独立测试就保持开发验证口径。

Git 执行前快照必须先生成。运行脚本拒绝覆盖成功目录；运行中不得改已冻结的实验代码/计划，技术故障另存说明和新版本。最终把接受、拒绝和方法局限追加到账本及评审，不回填修改运行前承诺。
